## 一、系统架构与制作背景

在格斗游戏强化学习与自动化决策系统中，对局的**可视化复盘**与**高质量资产沉淀**是算法迭代和成果展示的关键环节。《真侍魂：霸王丸地狱变》（Samurai Shodown II）运行于 SNK NeoGeo 街机基板，具有独特的屏幕刷新率（约 59.1856 FPS）和严格的内存状态流转。

本流水线实现了从 **MAME 实机仿真捕获 -> 内存步级事件打点 -> 无损音频/视频转码 -> 多回合时空对齐 -> 自适应语速电竞解说词生成 -> 结构化 JSON 与标准 SRT 字幕导出** 的全自动化流水作业。

## 二、MAME 视频流捕获工程设计

### 2.1 渲染模式与后台稳定性保证 (`-video gdi`)
在 Windows 自动化训练与录像流水线中，传统 MAME 默认使用 Direct3D 9 (`-video d3d`) 渲染。在无人值守或桌面锁定、显示器休眠时，Direct3D 会因底层 DX 设备丢失（`Device Lost`）触发显卡驱动挂起（TDR），甚至导致整机死机蓝屏。

**流水线标准配置**：
- 采用纯软件渲染驱动 `-video gdi`，完全剥离对物理显卡 3D 渲染上下文的依赖；
- 配合 `-aviwrite <temp_file.avi>` 原生参数，直接从 MAME 渲染缓冲区逐帧拉取 60 FPS 原始 YUV/RGB 像素与 44.1 kHz 立体声 PCM 音频；
- 杜绝掉帧、音画撕裂或驱动崩溃。

### 2.2 仿真速率与物理时钟
- 训练和策略搜索支持 2x ~ 4x 渲染加速；
- **视频录制阶段严格采用 1x 真实速率（`speed=1`）**：保证 NeoGeo 内部计时器、按键扫描输入与音频采样率 100% 保持硬件级绝对同步。

## 三、FFmpeg 转码与色彩空间规范

MAME 录制的原始 AVI 文件体积庞大（15 秒即达 350MB~500MB），流水线调用 FFmpeg（`libx264` + `aac`）进行实时转码压缩：

```bash
ffmpeg -y -i temp_match.avi \
  -c:v libx264 -pix_fmt yuv420p -preset fast -crf 20 \
  -c:a aac -b:a 128k \
  output_match_VICTORY.mp4
```

- **视频编码器**：`libx264`，画质参数 `crf=20`（视觉无损，画质极佳）；
- **像素格式**：强制采用 `-pix_fmt yuv420p`，确保在 Windows 媒体播放器、macOS QuickTime、各大剪辑软件（PR / FCPX / 剪映）以及主流视频平台具备 100% 播放兼容性；
- **压缩比**：将 400MB 原始 AVI 高保真压缩至 **4MB ~ 9MB**，转码耗时仅约 1.2 秒。

## 四、Bo3 多回合状态机与事件采样

`Bo3MatchController`（位于 `src/bo3_controller.py`）负责接管连续比赛生命周期：

1. **回合起步 (Round Start)**：重置局内时钟，加载对应回合策略（如 R1 针对性压制、R2 防守时延确反）；
2. **血量连续追踪**：内存探针读取 P1（`0x108447`）与 P2（`0x1084A7`）实际 HP；
3. **局末判定 (Round Finish)**：
   - 某一方血量归零，裁判触发“一本（IPPON）”；
   - 比分累加（如 1-0、1-1、2-0）；
4. **局间等待 (Intermission Wait)**：
   - 自动注入安全等待动作（站立格挡 `7`），等待局间裁判判罚横幅、血条重新灌满、下一局角色就位；
5. **战后 10 秒庆祝特写 (Post-Match Celebration)**：
   - 比赛决胜达成后，通过 Lua Bridge 将模拟器置为 1x 物理速率，强制向后空转 10.0 秒；
   - 完整收录霸王丸帅气收刀、掏出酒壶仰天长啸畅饮美酒、以及屏幕显示胜出名台词全过程。

## 五、自适应电竞解说词生成引擎 (`commentary_engine.py`)

### 5.1 时间轴物理换算公式
NeoGeo 街机硬件基准帧率为：
$$FPS = 59.1856$$
在强化学习 Gym 环境（`SS2RoundEnv`）中，每个 Step 包含 2 帧仿真步长：
$$t_{\text{sec}} = \frac{\text{step} \times 2}{59.1856}$$
$$\text{frame} = \text{round}(t_{\text{sec}} \times 59.1856)$$

### 5.2 自适应语速调谐算法 (`fit_text`)
真人专业电竞/体育解说员的中文语速常态分布在 **3.5 ～ 4.8 字 / 秒**。
若固定文本模板，面对不同对战时长容易出现“短对局语速过快超载”或“长对局空白尴尬”。

本引擎设计了三段式分级自适应文本选择器：
```python
def fit_text(short_text: str, medium_text: str, long_text: str, duration_sec: float) -> str:
    target_chars = duration_sec * 4.2  # 黄金语速系数
    candidates = [short_text, medium_text, long_text]
    # 选取与可用时长最贴近的解说文案
    best = min(candidates, key=lambda c: abs(len(c) - target_chars))
    return best
```

### 5.3 Bo3 多回合智能切分与叙事结构
对于完整的 Bo3（三局两胜）比赛，解说词自动切分为清晰的阶段弧线：
1. **全场揭幕**：介绍对阵双方背景与流派特色；
2. **第一局交锋**：首局立回试探、破绽确反、首局拿下判定（1-0）；
3. **局间转场**：裁判报幕，赛点转换，局间心理解读；
4. **第二局绝杀 / 决胜局决战**：对手背水反扑、霸王丸逆势斩落、终局终结判罚（2-0 或 2-1）；
5. **战后特写三段式升华**：
   - **收刀入鞘**：展现剑豪宗师风范；
   - **饮酒大笑**：经典动作与胜利台词意境渲染；
   - **终场致辞**：报出最终大比分，宣布总决赛胜出。

## 六、交付物标准与质量保证

每次对局运行后，系统自动落盘三大发布产物：
1. **`.mp4` 录像**：H.264/AAC，60 FPS，立体声，画质清晰平滑；
2. **`_commentary.json` 数据集**：包含对局总步数、对局时长、毫秒级时间戳、起始帧/结束帧、字数统计、每秒字数密度、事件标签等；
3. **`.srt` 字幕文件**：工业标准 SubRip 格式，时间码精确到毫秒，直接挂载播放器即可看到完美贴合画面的解说台词。
